# 个人学习站运行手册

## 服务及访问边界

Compose 的 api、web 保留原名称；新增 worker（同 API 镜像）和 gateway（专用 Codex 镜像）。仅 Caddy 对公网开放 80/443；不映射 8000、3000、8091。gateway 只挂载 `private/codex`，不挂载数据库、项目根目录、Docker socket、SSH 或 SMTP 凭据。API 不持有订阅授权。

`.env` 增加 `OWNER_EMAIL`、`GATEWAY_IMAGE`、高熵随机 `AI_GATEWAY_TOKEN`。保留原有域名、加密密钥、邮件配置。OWNER_EMAIL 必须对应已有且已验证的本人账号。非所有者账号和旧记录保留，但私人模式拒绝访问。

所有业务数据在 `data/growth.db`；上传文件在 `data/uploads`；Codex 授权在 `private/codex/auth.json`（目录 700，文件 600，容器 UID 1000）。授权不进入代码仓库或公共备份。

## 更新前

1. 检查运行镜像、磁盘、内存、Git 未提交更改。记下旧 API/Web 镜像 ID，保留镜像标签。
2. 在服务器创建仅 root 可读的带时间戳备份目录。备份 `.env`、`compose.yaml`、线上 `Caddyfile` 和当前 commit。
3. 使用 SQLite `Connection.backup()` 创建数据库一致性备份；不可仅复制在线 `.db`。记录备份 SHA256，并用 SQLite `PRAGMA integrity_check` 验证。
4. Caddyfile 已有节点和订阅路由，不用仓库文件覆盖它；不运行 `docker compose down -v`。

## 更新

CI 在测试与生产构建通过后生成 `-api:<commit>`、`-web:<commit>`、`-gateway:<commit>` 三个不可变标签。当前工作分支为 `codex/personal-study`，不自动覆盖 `latest`。

将三个镜像变量设为同一发布 commit。先 pull，再仅重建 api、web、gateway、worker。数据库启动时以事务执行 schema v2，原有有日期的任务转入新待办；旧目标树仍保留。接口返回 HTTP 409 表示版本过期或时间冲突，刷新/编辑后重试。

网关首次授权：在专用容器里运行 `codex login --device-auth`，根据官方提示完成 ChatGPT 授权；也可按官方认证文档将已有授权安全迁移至专用目录。`codex login status` 应显示 ChatGPT。不设置 `OPENAI_API_KEY`，不复制整个个人 Codex 配置目录。授权失效时重新登录并重启 gateway。

## 验收

- `/api/health` 返回 ok；未登录 `/today` 跳转登录，`/api/v1/overview` 返回 401。
- 本人登录后测试待办新增/勾选/撤销、周日程、词汇和跑步；刷新确认持久化。
- 内部 gateway 完成最小 JSON 推理；worker 能将真实生成结果保存为草稿。新闻必须有来源和发布时间。
- 查看容器健康、错误日志与内存；确认原节点域名和订阅路由的 Caddy 配置未变。
- 计划、课表和词义补全均先预览确认，不直接替换本人记录。

## 回滚

停止 worker 和 api 写入。先另存改版后数据库的一致性备份，避免丢失新增数据。恢复已验证的旧数据库、旧 `.env`、旧 Compose；重新启动旧 api/web 镜像。Caddy 不重建。新旧 schema 不应混用；保留新数据库供之后迁移恢复。

## 调度与来源

worker 每 20 秒检查北京时间任务，使用数据库 dedup_key 防止重复日报/周计划。正在执行的任务租期 15 分钟，进程重启后可恢复；取消任务不会落地模型结果。额度或授权失败最多自动重试 3 次，间隔 2 小时，之后可手动重试。

目前固定来源为中新网、BBC World、OpenAI、Google Research、World Athletics、Athletics Weekly。只处理最近 48 小时、有发布时间和 HTTP(S) 来源的条目，最多每类精选 3 条。来源少于目标数量时按实际内容显示。2026-10-21 实测 World Athletics RSS 不可用，其他来源覆盖了四类；失败信息展示在当期日报。RSS 摘要内容有限，站内英文摘要不是全文翻译。

若服务在周日的生成时段离线，恢复后可在周日程手动生成本周/下周草稿。当前未对错过的周日执行无限追补，避免恢复后集中消耗额度。每日新闻会在当天计划时间后恢复补抓。

每天维护独立数据库备份与私密配置备份；自动异地备份尚未配置。不要将私有用户记录或订阅授权上传到公开服务。
